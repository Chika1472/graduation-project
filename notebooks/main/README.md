# 본 분석 실행

## 실행 순서

1. `00_전체실행.ipynb`: 기초 입력 검증 → 공연·상권 연결 → 외식업 데이터셋 → 고정효과·GEE → RDF → 분석 도구.
2. `01_시간대확장_실행.ipynb`: 공연 예정시간 노출 → 시간대 매출 패널 → 시간창 분석.
3. `02_수정분석_실행.ipynb`: 현재 분기 예정회차 데이터셋 → 수정 분석 → 표본 진단 → 결과 보고서.

기존 고정 입력이 있으면 개별 실행도 가능합니다. 수집은 이 실행에 포함되지 않습니다. 프로젝트의 `requirements.txt`와 기존 과학계산 Python 환경을 사용합니다.

## 코드 위치

- `analysis/`: 01~13 분석 노트북
- `reporting/`: 근거 정리·진단·보고서 생성 노트북
- 고정 입력·분석 계획: `../../metadata/main/`
- 본 분석용 데이터: `../../data/analysis/final/`
- 계산 결과: `../../results/main/`
- 읽는 보고서: `../../reports/main/`

## 보고서 생성

- 기준선 보고서: `reporting/01_보고서_근거.ipynb` → `02_분석보고서_생성.ipynb`
- 시간정보 가용성: `reporting/03_공연시간정보_활용가능성.ipynb`
- 비유의성 진단: `reporting/04`, `05`, `06` → `07`
- 현재 분기 보고서: `02_수정분석_실행.ipynb`에 포함된 `reporting/09` → `08`

통계 기준과 표본 규칙은 폴더 정리로 변경하지 않습니다. 원자료와 이전 보관본을 수정하지 않으며, 미제공 매출을 0원으로 채우지 않습니다.
