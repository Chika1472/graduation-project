# 졸업프로젝트 작업 규칙

- 새 분석·전처리·시각화·데이터 수집 코드는 모두 Jupyter Notebook(`.ipynb`)으로 저장한다. 별도 `.py` 분석 소스를 새로 만들지 않는다.
- 한국어 Markdown 설명 → 짧은 코드 셀 → 표·그래프 → 해석 순서로 작성한다. 위에서 아래로 새 커널에서 실행 가능해야 한다.
- 현재 기본 연구 범위는 종로구·마포구, 공개 상권자료의 외식업 10종 전체, 2023~2025년 분기 자료이다. 01·02·05는 기존 한식음식점·커피음료 기준선이며, 현재 분석은 03·04의 연결 검증 → 08~10의 외식업 전체 분석 → 06·07의 RDF·분석 도구 순서로 실행한다.
- `data/raw/`는 원본 보관용이며 수정하지 않는다. 분석용 파생 자료는 `data/analysis/`, 결과는 `reports/`에 저장한다.
- 미제공 매출을 0원으로 채우지 않는다. 분기 자료를 일별 자료로 해석하지 않는다.
- 공연·시설의 공식 ID 연결과 시설명 임시 연결을 구분한다. 좌표 미수집과 현재 경계의 한계를 결과에 표시한다.
- `scripts/`는 이전 작업 이력이다. 새 작업에서 이 폴더의 `.py` 파일을 확장하지 말고 필요한 로직을 노트북으로 작성한다.
- 인증키는 프로젝트 외부 설정 또는 환경변수에서 읽고, 노트북 소스·출력·공유 파일에 포함하지 않는다.
- API 접근 차단 응답이 발생하면 요청을 중단한다. 단, 사용자 지정에 따라 KOPIS 수집 CLI는 정상 호출 간격을 1초로 하고 HTTP 400 응답은 3초 뒤 같은 ID로 재시도한다. 400이 계속되면 성공 또는 사용자 중지까지 반복하며, 그 외 차단 응답은 중단한다. 이 프로젝트의 분석 노트북은 네트워크 요청 없이 실행한다.
- 재수집 원문은 `data/raw/`의 새 회차 폴더에 추가한다. 분석에는 검증된 입력 매니페스트와 고정 스냅샷을 사용하고, 수집 중인 CSV를 직접 읽지 않는다. 이전 결과의 계산 검증에는 `data/analysis/baseline_two_industry/`의 고정 입력을 사용한다.
