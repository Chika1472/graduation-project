## 1. 연구 주제

### 배경과 동기

공연 관람 전후의 식사·음료 소비는 주변 음식점과 카페의 매출로 이어질 수 있다. 하지만 공연 자료(KOPIS)와 상권 자료(서울시)는 시간 단위·공간 단위·측정 단위가 서로 달라서, 그대로 연결하면 분석과 해석이 쉽게 틀어진다. 예를 들어 분기 자료를 월별이나 일별로 읽거나, 미제공 매출을 0원으로 채우거나, 같은 공연을 여러 상권에서 중복으로 세는 경우다.

김태경 교수님이 참여한 업종 간 공간적 관계 연구(고품질 음식점과 호텔 성과)에서 문제의식을 가져왔다. 이 연구는 그 관점을 **공연 → 외식업**으로 넓힌 사례이며, 원 논문의 자료나 식별 전략을 재현하지는 않는다.

### 연구 질문

| 구분 | 질문 | 성격 |
|---|---|---|
| **RQ1 매출 규모** | 같은 상권에서 공연 활동이 평소보다 많은 분기에 외식업 매출도 다른가? | 핵심 실증 |
| **RQ2 매출 구성** | 야간(21~24시) 매출은 공연 활동과 어떤 관계를 보이며, 업종별로 다른가? | 핵심 확장 |
| **RQ3 서비스 성능** | 온톨로지를 쓰면 AI의 단위·기간·공간 결합 오류가 줄어드는가? | 핵심 시스템 |
| RQ4 추가 탐색 | 주말 비중, 장르, 시차, 공연 시간창에서 추가 패턴이 보이는가? | 선택 |

방향과 크기를 미리 정하지 않고 양측 검정과 신뢰구간으로 보고한다. 결과는 **관련성**으로 해석하며 인과효과로 단정하지 않는다.

### 연구의 구성

| 단계 | 산출물 |
|---|---|
| ① 데이터셋 구축 | 공연·공연장·상권·업종·분기별 매출을 연결한 패널 |
| ② 온톨로지 구축 | 기간·장소·업종·측정 단위·출처·허용되는 결합 규칙을 RDF로 정의 |
| ③ Agentic AI 구축 | 자연어 질문을 개념 조회 → 자료 결합 → 통계 도구 실행 → 근거 설명으로 바꾸는 단일 에이전트 |
| ④ 분석 및 평가 | 업종별 관련성 분석, 데이터 사전 기반 에이전트와 온톨로지 기반 에이전트의 오류·성공률 비교 |

## 3. 연구 방법론

### 3.1 데이터셋 구축

1. 원본 CSV·API 응답 → 열 이름·타입 통일 → 상권·업종·분기 키 검사(일대일 결합 강제)
2. 공연 → 공연장: **공식 시설 ID 연결**과 **시설명 임시 연결**을 구분해 기록한다.
   - 공식 ID 연결은 13,727건, 시설명 잠정 연결은 16,320건이다.
   - 연구 범위 부분 그래프에는 공식 연결만 사용한다.
3. 공연장 → 상권: 미터 단위 투영 좌표계로 거리를 계산하고, 500m 이내 관계를 모두 연결한다(최단 1개만 고르지 않음).
4. 분기별로 공연 노출을 집계하고 매출·점포와 결합한다.
5. 결측을 처리하고 표본 제외 사유를 보고한다.
   - **미제공 매출은 0원으로 채우지 않는다.** 실제로 0원이 제공된 값은 그대로 유지한다.
   - 분기 자료를 일별 자료로 해석하지 않는다.
   - 점포는 일반·프랜차이즈·전체로 구분한다. 일반점포가 0이고 프랜차이즈가 양수인 행은 오류가 아니다.
   - 매출 모집단이 확인되기 전에는 점포당 매출을 만들지 않는다.

### 3.2 공연 활동(노출)의 측정

| 지표 | 정의 | 사용 단계 |
|---|---|---|
| 등록 공연 ID 수 | 분기와 공연 기간이 겹치는 공연 ID 수 | 기준선 분석 |
| **예정 시작회차** | 등록 기간에 상세정보의 정규 요일·시각을 반복해 만든 분기 내 시작 횟수 | 수정 분석(현재 기본) |
| 예정 시간창 노출 | 시작시각 + 러닝타임으로 추정한 종료 후 0~3시간, 3~6시간 등이 매출 시간대와 겹치는 분량 | 시간창 탐색 |

예정 시작회차는 실제 회차나 관객 수가 아니다. 휴연, 과거 일정 변경, 공휴일 특수 일정은 반영하지 못한다.

### 3.3 공간 연결

- **기준선:** 공연장 점과 상권 폴리곤 사이의 최단거리가 500m 이하인 관계. 민감도 분석에는 300m와 800m를 쓴다.
- **수정 분석:** 상권 중심점에서 500m 이내인 시설을 기본으로 한다. 기존 최단거리 연결은 비교 사양으로 남겼다.
- 500m는 공연 노출을 상권에 부여하는 규칙이다. "공연장 500m 안 음식점만의 매출"을 뜻하지 않는다.

### 3.4 통계 모형

**기본 고정효과 모형**

```
Y(a,s,t) = α(a,s) + λ(s,t) + β_s · ln(1 + E(a,t)) + ε(a,s,t)
```

| 기호 | 의미 |
|---|---|
| a, s, t | 상권, 업종, 분기 |
| α(a,s) | 상권×업종 고정효과: 상권·업종의 변하지 않는 차이 |
| λ(s,t) | 업종×분기 고정효과: 업종별 공통 분기 변화 |
| β_s | 업종별 공연 활동 계수 |

- **결과변수**
  - 기준선: ln(총매출), 야간 비중(%)
  - 수정 분석: ln(1+총매출액), ln(1+21~24시 매출액). 비중은 기술통계로만 쓴다.
- **추론:** 상권 군집 표준오차(CR1)와 t(G−1) 분포를 쓴다. 신뢰구간은 개별 95% 구간이다.
- **다중검정:** Benjamini–Hochberg(BH)와 Holm으로 보정한다. 미추정 결과는 p=1로 포함한다.
- **효과 크기 표기:** "1+노출이 2배일 때 매출+1의 조건부 기하평균 상대차이(%)"로 표기한다.

**보조·민감도 분석**

- 거리 300/500/800m, 균형표본, 일반점포·전체점포 통제
- within-between GEE와 고정효과 결과 비교
- 공연 시간창 모형: 6개 시간대 매출에 상권×업종×분기 고정효과를 더한 시간대 상대 패턴
- 공간 표준오차 민감도: 가우시안 커널, 대역폭 1km

**사전 고정 원칙**

- 수정 분석의 4개 사양(중심점 100%, 중심점 90%, 최단거리 100%, 같은 표본의 ID 수)은 회귀 결과를 보기 전에 `jupyter-notebook/20261006/metadata/revised_quarterly_plan.json`에 고정했다.
- p값에 따라 사양을 고르지 않는다.

### 3.5 온톨로지와 분석 도구

- **RDF 지식그래프**(`jupyter-notebook/20261006/notebooks/07`)는 공연·시설·상권·업종·분기·지표의 관계와 단위·집계 규칙·출처를 RDFLib으로 표현한다.
  - 무결성 검사를 함께 수행한다.
  - 큰 집계 테이블은 CSV로 두고, 그래프는 의미와 관계를 관리한다.
- **분석 도구**(`jupyter-notebook/20261006/notebooks/08`)는 구조화된 요청으로 지표·집계·모형·품질을 조회하는 오프라인 도구 5종이다.
- **설계 원칙**
  - LLM이 숫자를 직접 만들지 않고, 계산은 검증된 도구가 맡는다.
  - "공연이 매출을 증가시킨다" 같은 인과관계를 온톨로지에 사실로 넣지 않는다.

### 주요 결과 요약

**① 기준선 분석: 등록 공연 ID 수, 최단거리 500m**

- 총매출과 야간 비중 모두에서 10개 업종 계수 전체에 대한 결합 검정이 유의하지 않았다.
  - 총매출: p=0.79
  - 야간 비중: Holm 보정 p=0.38
- 보정 전 p<0.05는 야간 비중 2건(치킨 +1.10%p, 한식 −0.39%p)이었다. BH 보정 후에는 0건이었다.

**② 공연 시간창 탐색: 종료 후 0~3시간 등 4개 창**

- 종료 후 0~3시간의 공통 기울기는 −0.040, 95% CI는 [−0.105, +0.024]였다.
- 업종별 40개 검정 중 보정 전에도 유의한 결과가 없었다.

**③ 비유의성 진단**

- 데이터 수집 실패나 계산 오류는 아니었다. 기존 64개 결과를 재현했고 최대 차이는 약 2×10⁻¹⁶이었다.
- 대신 다음과 같은 구조적 원인이 확인됐다.
  - **측정이 연구 질문보다 넓다:** 분기 집계, 등록 공연 ID 수 사용, 관객 수 미관측
  - **비교에 쓸 수 있는 변동이 적다:** 고정효과로 공통 변화를 제거하면 노출 변동이 줄어들고, 일부 업종은 정보가 소수 상권에 몰려 있다.
  - **업종별 표본이 다르다:** 매출 미제공 여부에 따라 업종마다 관측되는 상권이 다르다.
  - **노출이 겹친다:** 공연 ID의 99%가 둘 이상의 상권에 연결된다.

**④ 수정 분석: 예정 시작회차, 중심점 500m, 총매출액·야간 매출액**

- 주 표본은 5,015행, 114개 상권, 10개 업종이다.
- 사전에 고정한 4개 사양 × 2개 결과 × 10개 업종, 총 80개 결과 모두 보정 전부터 p≥0.05였다.
  - 예: 한식 총매출 **+0.32% [−2.52%, +3.24%]**, 패스트푸드 총매출 **+5.18% [−3.61%, +14.77%]**
- 한식은 0에 가까운 작은 범위로 추정됐다. 패스트푸드처럼 상당한 양의 관계도 배제하지 못하는 업종도 있다.
- **대표성 제약:** 일정 가용률 100% 기준은 공연 밀집 상권을 크게 제외한다.
  - 대학로(혜화역)와 홍대입구역(홍대)은 기본 표본에서 빠졌다.
  - 분기 후보 공연이 100개 이상인 관측은 2.84%만 남았다.

**⑤ 보조 실험** (`jupyter-notebook/sandbox/`, 본 연구에 반영하지 않음)

- **실제자료 사후 탐색:** 580개 검정 중 보정 전 p<0.05는 16개였고, 전체 BH 보정 후에는 0개였다.
- **합성 효과 주입 모의실험:** 10개 업종에 같은 효과가 있고 공간 상관이 없다는 가정에서 계산했다.
  - 실제 효과가 5%라면 BH 보정 후 검출률은 한식 약 87%, 커피 약 45%, 패스트푸드 약 18%다.
- 이 결과는 실제 효과의 존재 확률이 아니다. 업종별 정밀도의 차이를 보여 주는 참고자료다.

> **결론의 표현:** 유의하지 않은 결과는 "공연의 소비 효과가 없다"는 증거가 아니다. 이 결과가 말해 주는 것은 정해진 공개자료와 표본에서 **뚜렷한 분기 단위 관련성을 확인하지 못했다**는 점이다. 지표 정의, 공간 연결, 일정 가용성에 따라 표본과 결과가 달라진다는 점도 함께 연구 결과로 제시한다.

## 5. 연구의 한계

- **노출 측정:** 예정회차와 공연 ID 수는 실제 상연 횟수나 관객 수가 아니다. 과거 일정 변경과 휴연은 반영하지 못한다.
- **시간 해상도:** 매출은 분기 합계다. 공연 직후 몇 시간의 소비를 직접 관측하지 못한다.
- **공간:**
  - 현재 시설 좌표와 현재 상권 경계를 과거 분기에 적용했다.
  - 상권 전체 매출에는 공연장에서 먼 곳의 소비도 섞여 있다.
  - 여러 상권이 같은 공연을 공유한다.
- **표본:**
  - 작은 상권·업종에서 매출이 선택적으로 미제공된다.
  - 업종별로 관측 상권이 다르고, 10개 업종이 모두 관측되는 공통표본은 13개 상권뿐이다.
  - 공연 밀집 상권이 제외됐다.
- **식별:** 고정효과로도 지역별로 시간에 따라 변하는 요인(관광, 유동인구, 날씨, 다른 행사)은 제거하지 못한다. 따라서 결과는 인과효과가 아니다.

## 6. 앞으로의 진행 방향

남은 일은 **(A) 실증분석 보강**과 **(B) 원래 계획의 시스템 부분(온톨로지·AI·평가) 완성**으로 나뉜다. 졸업프로젝트의 최소 완성 기준은 다음 다섯 가지다. 통계적 유의성이나 온톨로지의 우월성은 완성 기준이 아니다.

- 결합 데이터셋
- 문서화한 의미·검증 규칙
- 재현 가능한 분석
- 작동하는 단일 에이전트
- 비교 평가

### A. 실증분석 보강

1. **공연 밀집 상권의 일정 검증**
   - 대학로·홍대처럼 기본 표본에서 빠진 핵심 상권의 후보 공연부터 원문 일정을 확인한다.
   - 실제 날짜·회차·휴연 이력을 대조한다(점검 목록: `jupyter-notebook/sandbox/reports/06_core_verification_priority.csv`).
   - 그다음 이 상권들을 넣었을 때 결과가 유지되는지 확인한다.
2. **노출 지표 개선**
   - KOPIS 통계 API(상연 횟수, 티켓 판매 수)를 시험 조회한다.
   - 기간 기준(공연일/예매일)과 키 연결을 검증한 뒤 예정회차와 비교한다.
   - 현재 좌석 수는 과거 좌석이나 관객 수로 대체하지 않는다.
3. **정밀 매출 자료 확보**
   - 서울시 빅데이터캠퍼스 B079(일자 × 6개 시간대, 가맹점 격자)의 이용신청과 방문 일정을 확인한다.
   - 신청서 초안은 `reports/20261006/data_access/`에 있고, 아직 제출하지 않았다.
   - 확보 전까지는 새로운 시간창을 반복 탐색하지 않는다.
   - 6구간 자료로도 정확한 "종료 후 3시간" 매출은 복원할 수 없다는 점을 전제로 설계한다.
4. **검정력 기반 설계**
   - 의미 있는 효과 크기를 먼저 정하고, 그 크기를 검출하는 데 필요한 표본·시간창을 모의실험으로 정한다.
   - 충분히 좁은 구간이 0 주변에 남으면 그것도 연구 결과로 보고한다.

### B. 온톨로지·Agentic AI·평가

1. **온톨로지 확장**
   - 야간 매출, 점포(일반/프랜차이즈/전체), 회귀 실행 기록(AnalysisRun)을 RDF에 추가한다.
   - 단위·기간·공간 결합 규칙을 SHACL 또는 그에 준하는 결정적 검증 함수로 검사한다.
2. **에이전트 구현**
   - 도구 호출을 지원하는 LLM 1종을 기존 오프라인 도구 5종에 연결한다.
   - 단일 에이전트로 개념 해석 → 패널 조회 → 허용된 모형 실행 → 근거 카드 생성을 수행한다.
   - 지원하지 않는 질문(공연 직후 3일 매출, 개별 점포 매출 등)은 숫자를 만들지 않고 거절한다.
3. **웹 시제품**
   - 질문 입력, 분석 조건, 결과 그래프·표, 근거(출처·실행 ID) 화면으로 구성한 간단한 Python 웹 UI를 만든다.
4. **비교 평가**
   - 데이터 사전 기반 에이전트와 온톨로지 기반 에이전트를 같은 LLM·데이터·도구·검증 기능으로 비교한다.
   - 평가 30문항(단순 조회 6, 다중 결합 8, 회귀·사양 비교 8, 답할 수 없는 요청 8) × 2조건 × 3회로 실행한다.
   - 지표는 과제 성공률, 수치 정확도, 오류 유형(월·분기 혼동, 중복 집계, 단위 혼동), 지원 불가 판단, 비용이다.

### C. 마무리

- 위 결과를 졸업논문으로 정리하고, 새 환경에서 고정 데이터로 핵심 결과를 다시 실행할 수 있는지 확인한다.
- 시연을 준비한다.
- 일정이 부족하면 선택 분석 → 시설별 티켓 지표 → 시차 분석 → 화면 부가 기능 순서로 줄인다. 데이터 품질 검사, 기본 분석, 비교 평가, 출처 기록은 줄이지 않는다.


이 PC에서는 `start-jupyter.cmd`를 실행한다. 현재 분석은 `jupyter-notebook/20261006/02_수정분석_실행.ipynb`, 기준선은 `00_전체실행.ipynb`, 시간창 분석은 `01_시간대확장_실행.ipynb`를 사용한다.

다른 Windows x64 PC에서는 프로젝트 폴더 전체를 옮긴 뒤 `powershell -ExecutionPolicy Bypass -File environment/setup.ps1`로 환경을 재생성한다. `.venv`를 그대로 옮겨 재사용하지 않는다. 자세한 설명은 [재현 환경 안내](environment/README.md)에 있다.

원자료와 과거 결과의 JSON·CSV 경로는 당시 기록을 유지한다. `environment/project_paths.ipynb`가 이를 현재 위치로 해석한다. 분석은 로컬 입력만 사용하며 KOPIS 수집기는 실행하지 않는다. 기존 결과를 보존하며 점검하려면 [재현 검증 노트북](environment/verify_reproduction.ipynb)을 실행한다.
